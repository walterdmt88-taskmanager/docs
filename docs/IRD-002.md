# IRD-002 — task-service

**Scope:** Task creation, status transitions, comments, and the tasks database.  
**Linked DOP:** DOP-001 AC-03, AC-04, AC-05, AC-06, AC-07  
**Depends on:** user-service (JWT payload carries `userId` and `role` — task-service does not call user-service at runtime)  
**Used by:** api-gateway (routes `/tasks` here after JWT validation)

---

## What this service does

`task-service` owns every task record and every comment. It trusts the `X-User-Id` and `X-User-Role` headers set by the gateway — it never validates the JWT itself. It stores `assignee_id` and `author_id` as plain UUIDs (copied from the JWT or request body) and never joins to the user database.

---

## Technology choices

Same language and framework stack as user-service (TypeScript + Node.js 20 + Express 4 + PostgreSQL 16 + raw SQL via `pg`). No additional libraries beyond what user-service uses.

## API contract

All endpoints require headers injected by the gateway:
- `X-User-Id: <uuid>` — the authenticated user's ID
- `X-User-Role: member | lead` — the authenticated user's role

Requests missing these headers return `401 { "message": "unauthorized" }`.

---

### POST /tasks — Create a task

**Request body:**
```json
{
  "title":       "string  (required · max 200 chars)",
  "description": "string  (optional · max 2000 chars)",
  "assignee_id": "uuid    (required · ID from user-service)",
  "due_date":    "string  (optional · ISO 8601 date: YYYY-MM-DD)"
}
```

**Success — 201 Created:**
```json
{
  "id":          "uuid",
  "title":       "string",
  "description": "string | null",
  "status":      "todo",
  "assignee_id": "uuid",
  "created_by":  "uuid",
  "due_date":    "YYYY-MM-DD | null",
  "created_at":  "ISO8601 timestamp",
  "updated_at":  "ISO8601 timestamp"
}
```

**Error responses:**

| HTTP | Condition | Body |
|---|---|---|
| 400 | Missing `title` | `{ "message": "title is required" }` |
| 400 | Missing `assignee_id` | `{ "message": "assignee_id is required" }` |
| 400 | `assignee_id` not a valid UUID | `{ "message": "assignee_id must be a valid UUID" }` |

---

### GET /tasks — List tasks

**Query parameters:**

| Param | Values | Behavior |
|---|---|---|
| `assignee` | `me` or a UUID | Filter by assignee. If omitted and caller is `member`, defaults to their own tasks. If caller is `lead`, returns all tasks. |
| `status` | `todo` \| `in_progress` \| `done` | Filter by status. Optional. |

**Success — 200 OK:**
```json
{
  "tasks": [
    {
      "id": "uuid",
      "title": "string",
      "status": "todo | in_progress | done",
      "assignee_id": "uuid",
      "due_date": "YYYY-MM-DD | null",
      "created_at": "ISO8601 timestamp"
    }
  ],
  "total": 12
}
```

Ordered by `created_at` descending (newest first).  
Empty result returns `{ "tasks": [], "total": 0 }` — never a 404.

### GET /tasks/:id — Get one task (with comments)

**Success — 200 OK:**
```json
{
  "id": "uuid",
  "title": "string",
  "description": "string | null",
  "status": "todo | in_progress | done",
  "assignee_id": "uuid",
  "created_by": "uuid",
  "due_date": "YYYY-MM-DD | null",
  "created_at": "ISO8601 timestamp",
  "updated_at": "ISO8601 timestamp",
  "comments": [
    {
      "id": "uuid",
      "author_id": "uuid",
      "text": "string",
      "created_at": "ISO8601 timestamp"
    }
  ]
}
```

**Error:** `404 { "message": "task not found" }`

---

### PATCH /tasks/:id/status — Update status

**Request body:**
```json
{ "status": "todo | in_progress | done" }
```

**Success — 200 OK:** Returns the full updated task object (same shape as POST /tasks response).

**Error responses:**

| HTTP | Condition | Body |
|---|---|---|
| 400 | Invalid status value | `{ "message": "status must be one of: todo, in_progress, done" }` |
| 403 | Caller is not the assignee or creator | `{ "message": "you do not have permission to update this task" }` |
| 404 | Task not found | `{ "message": "task not found" }` |

## Data model

Database: `tasks_db`

```sql
CREATE EXTENSION IF NOT EXISTS "pgcrypto";

CREATE TABLE tasks (
  id          UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  title       VARCHAR(200) NOT NULL,
  description TEXT,
  status      VARCHAR(20)  NOT NULL DEFAULT 'todo'
                           CHECK (status IN ('todo', 'in_progress', 'done')),
  assignee_id UUID        NOT NULL,  -- user-service user.id — stored as ID, no FK
  created_by  UUID        NOT NULL,  -- user-service user.id — same
  due_date    DATE,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_tasks_assignee   ON tasks (assignee_id);
CREATE INDEX idx_tasks_status     ON tasks (status);
CREATE INDEX idx_tasks_created_at ON tasks (created_at DESC);

CREATE TABLE comments (
  id         UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  task_id    UUID        NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  author_id  UUID        NOT NULL,   -- user-service user.id — stored as ID, no FK
  text       VARCHAR(1000) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_comments_task ON comments (task_id);
```

**Cross-service reference rule:**  
`assignee_id`, `created_by`, and `author_id` are UUIDs that correspond to rows in `user-service`'s `users` table. There is **no foreign key** between `tasks_db` and `users_db`. task-service never connects to users_db. If a user is deleted from user-service, their tasks remain and their ID is still stored — cleanup is a future concern.

## Status transition rules

```
todo  →  in_progress  →  done
todo  →  done                    (allowed — skip in_progress)
done  →  in_progress             (allowed — reopen)
done  →  todo                    (allowed — reopen to start)
```

Any valid `status` value can be set from any other valid status. No enforced linear progression.

---

## Authorization rules

| Action | Who can do it |
|---|---|
| Create a task | Any authenticated user |
| List tasks | `member` sees only their own · `lead` sees all |
| Get one task | Any authenticated user |
| Update task status | Only the task's `assignee_id` or `created_by` |
| Add a comment | Any authenticated user |
