## 1. Context

DOP-002 defines the image policy at the area level. This IRD specifies how each service's Dockerfile must be written — base images, build stages, user policy, health checks, and port exposure. It is the implementation contract that DOP-002 acceptance criteria are verified against.

---

## 2. Inputs

- Application source code and `package.json` per service
- `.env.example` for environment variable documentation
- `tsconfig.json` for TypeScript compilation

---

## 3. Outputs

- A production Docker image per service, pushed to ECR
- Image URI: `905418181527.dkr.ecr.eu-central-1.amazonaws.com/taskmanager-<service>:<semver>`

---

## 4. Build Stage Standards

All Dockerfiles must use multi-stage builds with these named stages:

| Stage | Purpose |
|---|---|
| `deps` | Install production `node_modules` only (`npm ci --only=production`) |
| `builder` | Install all deps, copy source, compile TypeScript (`npm run build`) |
| `runner` / `production` | Copy `node_modules` from `deps` + `dist` from `builder` — no source, no dev deps |

**Rule:** The final stage must not contain TypeScript source files or dev dependencies.

---

## 5. Base Image Standards

| Service type | Base image | Stage |
|---|---|---|
| Node.js (all stages) | `node:20-alpine` | deps, builder, runner |
| Frontend static server | `nginx:alpine` | production |

**Rule:** Never use `:latest`. Pin to `node:20-alpine` and `nginx:alpine` explicitly.

---

## 6. User Policy

| Service | Standard | Current state |
|---|---|---|
| All Node.js services | `USER node` (built-in non-root user) | Inconsistent — see gaps |
| frontend-service | root (nginx requirement) | Known gap |

**Standard going forward:** All Node.js services use `USER node`. No custom `adduser` needed.

**Known gap:** `api-gateway` and `user-service` use a custom `appuser` instead of `USER node`. Align to `USER node` by Day 26.

**Known gap:** `frontend-service` runs nginx as root (required to bind port 80). Fix path: switch to `nginx:unprivileged` + expose port 8080. Deferred to Day 26.

---

## 7. Health Check

Every service Dockerfile must include a `HEALTHCHECK` directive:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=3 \
  CMD wget -qO- http://localhost:<PORT>/health || exit 1
```

| Service | Port |
|---|---|
| user-service | 3001 |
| task-service | 3002 |
| api-gateway | 8080 |
| notification-service | health port per service |
| frontend-service | 3000 (nginx) |

---

## 8. Acceptance Criteria

| ID | Criteria | Verify with |
|---|---|---|
| AC-01 | All Dockerfiles use multi-stage builds | `grep -r "AS builder" */Dockerfile` |
| AC-02 | All Node.js services use `node:20-alpine` | `grep -r "^FROM" */Dockerfile` |
| AC-03 | Final stage contains no TypeScript source | `docker run --rm <image> ls /app/src` → no such directory |
| AC-04 | All Node.js services run as non-root | `docker run --rm <image> whoami` → `node` or `appuser` |
| AC-05 | Every Dockerfile has a HEALTHCHECK | `grep -r "HEALTHCHECK" */Dockerfile` — all 5 services |
| AC-06 | No `:latest` tag in any Dockerfile | `grep -r "latest" */Dockerfile` returns nothing |

---

## 9. Known Gaps (fix by Day 26)

| Gap | Affected service | Fix |
|---|---|---|
| Custom `appuser` instead of `USER node` | api-gateway, user-service | Replace `addgroup/adduser` with `USER node` |
| nginx running as root | frontend-service | Switch to `nginx:unprivileged`, expose port 8080 |
