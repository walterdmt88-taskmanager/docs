## Objective

Define the Docker image policy for all services in the Task Management System — base images, build strategy, registry, tagging, and scanning rules. Every image produced by this project must conform to these rules before it is pushed or deployed.

---

## In Scope

- Dockerfile standards for all 5 services (user-service, task-service, api-gateway, frontend-service, notification-service)
- Multi-stage build requirement
- Approved base images
- ECR registry configuration
- Image tagging policy

---

## Out of Scope

- Terraform-managed ECR repository provisioning
- Image signing (Cosign / Notary)
- Automated image scanning in CI (deferred to Day 25)

---

## Approved Base Images

| Use case | Base image |
|---|---|
| Node.js services (build + runtime) | `node:20-alpine` |
| Frontend static file server | `nginx:alpine` |

**Rule:** No other base images without explicit team decision. Never use `:latest` tag in production.

---

## Build Strategy

All Dockerfiles use multi-stage builds:

| Stage name | Purpose |
|---|---|
| `builder` | Install deps, compile TypeScript |
| `runner` / `production` | Copy compiled output only, no dev deps |

**Rule:** Production stage must not contain `node_modules` with dev dependencies or TypeScript source files.

## Tagging Policy

| Environment | Tag format | Example |
|---|---|---|
| Production (EKS) | semver | `v1`, `v1.2` |
| Local dev | not pushed to ECR | — |

**Rule:** Never push `:latest` to ECR. Every ECR image must have a versioned tag.

## Acceptance Criteria

| ID | Criteria | Verify with |
|---|---|---|
| AC-01 | All Dockerfiles use multi-stage builds | `grep -r "AS builder" */Dockerfile` |
| AC-02 | All Node.js services use `node:20-alpine` base | `grep -r "FROM" */Dockerfile` |
| AC-03 | frontend-service production stage uses `nginx:alpine` | `grep "FROM nginx" frontend-service/Dockerfile` |
| AC-04 | No `:latest` tag in any EKS deployment manifest | `grep -r "latest" eks/03-app/` returns nothing |
| AC-05 | All ECR images follow `taskmanager-<service>:v<N>` naming | Review ECR repository list |
