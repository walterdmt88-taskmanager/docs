## Objective

Define the AWS infrastructure used to run the Task Management System in a production-equivalent environment — covering account structure, EKS cluster configuration, network topology, node policy, cost guards, and IAM rules.

---

## In Scope

- AWS account and region selection
- EKS cluster configuration (eksctl)
- Node group policy (instance type, spot usage, scaling)
- Network topology (VPC, subnets, NAT decision)
- Cost guards
- IAM policy (training account constraints)

---

## Out of Scope

- Terraform-managed infrastructure (all provisioning done via eksctl + manifests)
- Production-grade VPC with private subnets + NAT Gateway
- Multi-region or multi-account setup
- Production IAM hardening (federated SSO, SCPs)

## Network Topology

| Decision | Value | Reason |
|---|---|---|
| NAT Gateway | Disabled | Nodes in public subnets — saves ~$30/mo in training |
| VPC | Default AWS VPC | Training only — no custom VPC |
| Subnet type | Public | Cost optimization for training environment |

**Note:** In production, nodes must be in private subnets with NAT Gateway. Public subnets are a training-only decision.

## Acceptance Criteria

| ID | Criteria | Verify with |
|---|---|---|
| AC-01 | EKS cluster reachable and nodes Ready | `kubectl get nodes` |
| AC-02 | All app pods Running in `default` namespace | `kubectl get pods -n default` |
