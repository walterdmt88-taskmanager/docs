## Objective

Define how all services in the Task Management System are deployed, scaled, and managed in Kubernetes — covering manifest structure, namespace policy, autoscaling rules, secrets policy, and Helm usage.

---

## In Scope

- K8s deployment topology for all 5 services
- Namespace policy
- HPA (Horizontal Pod Autoscaler) configuration
- Secrets and ConfigMap policy
- Helm chart usage (Redis only)
- Cluster targets: minikube (local dev), EKS (production-equivalent)

---

## Out of Scope

- Terraform-managed cluster provisioning
- Service mesh (Istio / Linkerd)
- Multi-cluster deployment
- GitOps (ArgoCD / Flux) — deferred

---

## Cluster Targets

| Environment | Tool | Config location |
|---|---|---|
| Local dev | minikube | `k8s/taskmanager/` |
| Production-equivalent | EKS (eksctl) | `eks/` |

---

## Namespace Policy

| Namespace | Workloads |
|---|---|
| `default` | All app services (user-service, task-service, api-gateway, frontend-service, notification-service, databases, Redis) |
| `kube-system` | cluster-autoscaler only |

---

## Deployment Topology

| Service | Type | Min replicas | Max replicas |
|---|---|---|---|
| api-gateway | Deployment + HPA | 2 | 6 |
| user-service | Deployment + HPA | 2 | 4 |
| task-service | Deployment + HPA | 2 | 6 |
| notification-service | Deployment + HPA | 1 | 3 |
| frontend-service | Deployment | 1 | 1 (no HPA) |
| db-user | StatefulSet | 1 | 1 (no HPA) |
| db-task | StatefulSet | 1 | 1 (no HPA) |
| redis | Helm (bitnami/redis) | — | — |

**Rule:** HPA applies to stateless services only. StatefulSets (databases) are never autoscaled.

---

## HPA Policy

| Metric | Target |
|---|---|
| CPU utilization | 60% of pod request |
| Memory utilization | 70% of pod request |
| Scale-up stabilization | 0s (immediate) |
| Scale-down stabilization | 300s (5 min, prevents thrashing) |
| Scale-up increment | max 2 pods/min (api-gateway, task-service) / 1 pod/min (others) |
| Scale-down increment | max 1 pod/min |

**Requires:** metrics-server running in cluster (`kubectl top pods` must work).

---

## Helm Usage

| Chart | Release name | Values file |
|---|---|---|
| `bitnami/redis` | `my-redis` | `eks/redis-values.yaml` (EKS), `k8s/my-redis-values.yaml` (minikube) |

**Rule:** Only Redis is managed via Helm. All app services use raw K8s manifests.

---

## Secrets Policy

- All secrets created imperatively via `kubectl create secret` — never committed as plain YAML
- `.env` files gitignored — `.env.example` committed with no values
- K8s Secret objects referenced in deployments via `envFrom` or `secretKeyRef`

---

## Acceptance Criteria

| ID | Criteria | Verify with |
|---|---|---|
| AC-01 | All stateless services have HPA configured | `kubectl get hpa -n default` |
| AC-02 | No StatefulSet has HPA | `kubectl get hpa -n default` — no db entries |
| AC-03 | All pods have resource requests and limits defined | `kubectl describe pod <name>` |
| AC-04 | All pods have liveness and readiness probes | `kubectl describe pod <name>` |
| AC-05 | No K8s Secret YAML with real values committed | `grep -r "password:" eks/ k8s/` returns no real values |
| AC-06 | Redis deployed via Helm, release name `my-redis` | `helm list -n default` |
