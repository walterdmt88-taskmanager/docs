## Objective

Helm is used in this project to deploy bitnami/redis. This IRD documents the conventions that govern how charts are installed, upgraded, and rolled back so that every team member can reproduce the same state from the same files.

---

## Convention 1 — Values Override File Is Required

**Rule:** Never install or upgrade a Helm chart with raw `--set` flags in a CI/CD pipeline or documented runbook. All overrides live in a `values.yaml` override file committed to the repo.

**Why:** `--set` flags exist only in shell history. An override file is the source of truth that survives machine restarts and team changes. Reviewing "what is configured" requires reading one file, not reconstructing a command.

**Override file location:**

```
k8s/taskmanager/my-redis-values.yaml   ← bitnami/redis overrides
```

**Install command (canonical):**

```bash
helm install my-redis bitnami/redis \
  --namespace default \
  -f k8s/taskmanager/my-redis-values.yaml
```

**Upgrade command (canonical):**

```bash
helm upgrade my-redis bitnami/redis \
  --namespace default \
  -f k8s/taskmanager/my-redis-values.yaml
```

---

## Convention 2 — Release Name Is Fixed

**Rule:** The Helm release name for Redis is `my-redis`. Do not use a different name in development or production.

**Why:** The release name becomes a DNS hostname inside the cluster: `my-redis-master.default.svc.cluster.local`. Services that connect to Redis reference this hostname. Changing the release name breaks DNS resolution for every consumer without a config change.

**Redis hostname used by api-gateway:**

```
my-redis-master.default.svc.cluster.local:6379
```

This value must appear in the api-gateway ConfigMap or environment variable (`REDIS_URL`).

## Convention 3 — Required Override Settings (my-redis-values.yaml)

The values file must configure at minimum:

```yaml
architecture: standalone     # single master; no sentinel/cluster for training
auth:
  enabled: true              # password auth required — never disabled
  existingSecret: my-redis-secret    # Secret name (created via kubectl)
  existingSecretPasswordKey: redis-password
persistence:
  enabled: false             # training: no PVC needed for rate-limit counter
resources:
  requests:
    cpu: "100m"
    memory: "128Mi"
  limits:
    cpu: "250m"
    memory: "256Mi"
```

**Rule:** `auth.enabled` must never be `false`. Redis without auth in a K8s cluster is reachable by any Pod in the namespace.

**Secret creation (run once before helm install):**

```bash
kubectl create secret generic my-redis-secret \
  --from-literal=redis-password="<strong-password>"
```

---

## Convention 4 — Chart Repository Must Be Registered

Before any `helm install` or `helm upgrade`, the bitnami repo must be registered:

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
```

**Why documented here:** A fresh cluster or a new machine will fail `helm install` with "no repository entry" if this step is skipped. Document it once so it is never forgotten.

## Convention 5 — Upgrade and Rollback Runbook

### Check current state

```bash
# What is installed?
helm list -n default

# What version is it?
helm history my-redis -n default

# Is Redis responding?
kubectl exec -it deployment/api-gateway -n default -- \
  redis-cli -h my-redis-master.default.svc.cluster.local \
  -a <password> ping
# Expected: PONG
```

### Upgrade procedure

```bash
# 1. Edit k8s/taskmanager/my-redis-values.yaml with the change
# 2. Dry-run to preview
helm upgrade my-redis bitnami/redis \
  --namespace default \
  -f k8s/taskmanager/my-redis-values.yaml \
  --dry-run

# 3. Apply if dry-run looks correct
helm upgrade my-redis bitnami/redis \
  --namespace default \
  -f k8s/taskmanager/my-redis-values.yaml

# 4. Verify Pod is Running
kubectl get pods -n default -l app.kubernetes.io/instance=my-redis
```

### Rollback procedure

```bash
# List revision history
helm history my-redis -n default

# Roll back to previous revision
helm rollback my-redis 1 -n default

# Verify
kubectl get pods -n default -l app.kubernetes.io/instance=my-redis
```

---

## Convention 6 — Uninstall Removes All Resources

```bash
helm uninstall my-redis -n default
```

**Note:** If `persistence.enabled: true` was used, PVCs are NOT deleted by Helm uninstall. Delete them explicitly:

```bash
kubectl delete pvc -l app.kubernetes.io/instance=my-redis -n default
```

In the training config, `persistence.enabled: false`, so this step is not needed.

---

## Audit Checklist

Run before any Helm-related PR or session:

- [ ] `k8s/taskmanager/my-redis-values.yaml` exists and is committed
- [ ] `auth.enabled: true` in values file
- [ ] `my-redis-secret` exists in cluster — `kubectl get secret my-redis-secret`
- [ ] Release name is `my-redis` — `helm list -n default`
- [ ] `kubectl exec ... redis-cli ping` returns `PONG`
- [ ] No `--set` flags used in install/upgrade commands in any runbook or script
