## Docker Swarm on EC2 (Day 11)

### Architecture

```
Internet → EC2 manager (public IP) :8080 (api-gateway)
              │
         Swarm overlay network (app-net)
              ├── worker-1 → user-service, frontend-service
              └── worker-2 → task-service
```

### Config

| Resource | Value |
|----------|-------|
| Instance type | `t3.micro` (3 nodes) |
| AMI | Amazon Linux 2 (latest) |
| Security Group — manager | Inbound: 22 (SSH, your IP only), 8080 (HTTP, 0.0.0.0/0), 2377 (Swarm join, internal), 7946 (gossip, internal), 4789 (VXLAN, internal) |
| Security Group — workers | Inbound: 22 (SSH, your IP only), all from manager SG |

### Deploy command

```bash
docker stack deploy -c docker-compose.stack.yml taskmanager
```

## EKS Cluster (Day 18)

### Cluster config (`eks/cluster.yaml`)

| Property | Value |
|----------|-------|
| Cluster name | `taskmanager-chau-lab` |
| K8s version | 1.29 |
| Region | `eu-central-1` |
| Node group | `ng-1`, instance `t3.medium`, min 1 / max 3 / desired 2 |
| Managed | Yes (eksctl) |

### IAM requirements

eksctl creates the required IAM roles automatically:
- `eksctl-taskmanager-chau-lab-cluster-ServiceRole` — control plane IAM role
- `eksctl-taskmanager-chau-lab-nodegroup-NodeInstanceRole` — node IAM role

**Minimum node policies:**
- `AmazonEKSWorkerNodePolicy`
- `AmazonEKS_CNI_Policy`
- `AmazonEC2ContainerRegistryReadOnly`

### Deploy flow

```bash
# 1. Create cluster (15–20 min)
eksctl create cluster -f eks/cluster.yaml

# 2. Update kubeconfig
aws eks update-kubeconfig --name taskmanager-chau-lab --region eu-central-1

# 3. Apply manifests (Layer 1→4, see IRD-005)
kubectl apply -k eks/03-app/

# 4. Install Redis
helm install my-redis bitnami/redis -f k8s/taskmanager/my-redis-values.yaml

# 5. Verify
kubectl get pods,svc,ingress -n default
```

### Teardown (cost control)

```bash
# Delete all K8s resources first (releases ELB)
kubectl delete -k eks/03-app/
helm uninstall my-redis

# Delete cluster (releases nodes + control plane)
eksctl delete cluster --name taskmanager-chau-lab --region eu-central-1
```

**Rule:** Always run `kubectl delete` BEFORE `eksctl delete cluster`. Deleting the cluster first leaves an orphaned ELB that still costs money and cannot be auto-cleaned.

## ECS Fargate (Day 25)

Task definitions are in `ecs/task-defs/`. Each service has its own task definition JSON.

| Service | Task definition | CPU / Memory |
|---------|----------------|-------------|
| user-service | `ecs/task-defs/user-service.json` | 256 / 512 |
| task-service | `ecs/task-defs/task-service.json` | 256 / 512 |
| api-gateway | `ecs/task-defs/api-gateway.json` | 256 / 512 |
| frontend-service | `ecs/task-defs/frontend-service.json` | 256 / 512 |

**ECS vs EKS:**
- ECS Fargate: AWS manages the nodes (serverless containers). No cluster to provision. Good for simple workloads.
- EKS: You manage the node group (EC2 instances). Full K8s API. Good for complex workloads with existing K8s manifests.

For this system, EKS is the primary deployment target. ECS was built as a training exercise to understand the trade-offs.

## Terraform EKS Basics (Day 26)

Location: `tf-eks-basics/`

| File | Purpose |
|------|---------|
| `provider.tf` | AWS provider, region `eu-central-1` |
| `main.tf` | VPC + EKS cluster + node group |
| `output.tf` | cluster_name, cluster_endpoint, kubeconfig_command |
| `backend.tf` | S3 remote state (bucket must exist before `terraform init`) |

### Rules

- Remote state MUST be in S3 (`backend.tf`). Never use local state for EKS — the state file contains kubeconfig and IAM data.
- `terraform plan` before `terraform apply` — always review the diff
- `terraform destroy` tears down everything in the state file — confirm before running

### Verify

```bash
cd tf-eks-basics/
terraform init
terraform plan
# Expected: 0 changes (if cluster was created with eksctl and state matches)
```

## Security rules (apply to all AWS resources)

1. **SSH key pair** — never commit the `.pem` file. Store in `~/.ssh/`.
2. **SSH Security Group** — restrict port 22 to your IP (`$(curl -s ifconfig.me)/32`), not `0.0.0.0/0`.
3. **IAM least privilege** — node roles get only the 3 minimum policies. No `AdministratorAccess` on any training resource.
4. **Secrets in AWS** — DB passwords and JWT secrets in AWS Secrets Manager (or EKS Secrets). Never in EC2 user-data or ECS task definition env vars as plaintext.
5. **Cost alerting** — AWS Billing alert at $100 threshold. EKS control plane at $0.10/h is the main risk.
