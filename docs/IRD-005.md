## What this IRD covers

All Kubernetes manifests live in `k8s/taskmanager/`. This IRD documents the design decisions behind those manifests so that:
1. A new session can reconstruct the cluster state without re-exploring files
2. The system can be deployed to any K8s cluster (minikube or EKS) idempotently
3. Debugging sessions start with a mental model, not a file hunt

## Secrets (not in git)

Secrets are created with `kubectl create secret` before any manifest is applied. They are never stored in YAML files.

| Secret name | Keys | Who reads it |
|-------------|------|-------------|
| `user-svc-secret` | `DATABASE_URL`, `JWT_SECRET`, `BCRYPT_ROUNDS` | user-service Deployment |
| `task-svc-secret` | `DATABASE_URL` | task-service Deployment |
| `api-gw-secret` | `JWT_SECRET` | api-gateway Deployment |
| `db-user-secret` | `POSTGRES_PASSWORD` | db-user StatefulSet |
| `db-task-secret` | `POSTGRES_PASSWORD` | db-task StatefulSet |

**Rule:** `JWT_SECRET` must be the SAME value in `user-svc-secret` and `api-gw-secret`. The gateway verifies tokens the user-service signs — they must share the secret.

## StatefulSet design (databases)

Databases use StatefulSets, not Deployments. Key differences:

| Decision | Rule | Why |
|----------|------|-----|
| Headless Service (`clusterIP: None`) | Required for StatefulSet stable DNS | Lets the Pod be addressed as `db-user-0.db-user:5432` |
| `replicas: 1` | Single-node PostgreSQL only | No replication configured — test environment only |
| PersistentVolumeClaim | `ReadWriteOnce`, 1Gi | Data survives Pod restarts. Deleted when `kubectl delete pvc` |
| `postgres:15-alpine` | Pinned version | Never use `latest` — image changes silently break the schema |

## NetworkPolicy rules

`netpol.yaml` implements a default-deny architecture. Each policy is explicit:

| Policy | Allows | Denies |
|--------|--------|--------|
| `allow-api-gw-to-user-svc` | api-gateway → user-service:3001 | Everyone else |
| `allow-api-gw-to-task-svc` | api-gateway → task-service:3002 | Everyone else |
| `allow-user-svc-to-db-user` | user-service → db-user:5432 | Everyone else |
| `allow-task-svc-to-db-task` | task-service → db-task:5432 | Everyone else |

> Note: NetworkPolicies require a CNI plugin that enforces them (e.g., Calico, Cilium). On EKS, enable the AWS VPC CNI Network Policy feature. On minikube, install Calico.

## Ingress routing

```yaml
rules:
  - http:
      paths:
        - path: /api
          pathType: Prefix
          backend: api-gateway:8080
        - path: /
          pathType: Prefix
          backend: frontend-service:3000
```

`ingressClassName: nginx` — requires `ingress-nginx` controller installed in the cluster.

## Helm Redis

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm install my-redis bitnami/redis -f k8s/taskmanager/my-redis-values.yaml
```

After install, `helm get notes my-redis` shows the exact Service name. In dev: `my-redis-master:6379`.

The api-gateway reads `REDIS_URL=redis://my-redis-master:6379` from `api-gw-cm` ConfigMap.

**⚠️ OPEN GAP:** Rate-limit middleware is NOT implemented in api-gateway code (see DOP-001 AC-14 gap). Redis is provisioned but unused. This is a Linear issue to open.

## Layer-1 / Layer-2 / Layer-3 deploy order

Manifests must be applied in dependency order. Never `kubectl apply -k .` blind if the cluster is fresh.

```
Layer 1 — Storage + Config (no service dependencies):
  kubectl apply -f db-user-cm.yaml db-task-cm.yaml
  kubectl apply -f user-svc-cm.yaml task-svc-cm.yaml api-gw-cm.yaml
  kubectl create secret generic ... (manual)

Layer 2 — Databases (need ConfigMaps + Secrets):
  kubectl apply -f db-user-statefulset.yaml db-task-statefulset.yaml
  kubectl wait --for=condition=Ready pod/db-user-0 --timeout=60s
  kubectl wait --for=condition=Ready pod/db-task-0 --timeout=60s

Layer 3 — Application services (need databases ready):
  kubectl apply -f user-svc-deployment.yaml task-svc-deployment.yaml
  kubectl apply -f api-gw-deployment.yaml frontend-deployment.yaml

Layer 4 — Networking:
  kubectl apply -f ingress.yaml netpol.yaml
  helm install my-redis bitnami/redis -f my-redis-values.yaml
```

## Verification commands

```bash
# All pods running
kubectl get pods -n default

# Ingress address
kubectl get ingress taskmanager-ingress

# Test health through ingress
curl http://<ingress-ip>/api/health

# Redis
kubectl exec -it $(kubectl get pods -l app.kubernetes.io/name=redis -o name | head -1) \
  -- redis-cli ping
# Expected: PONG
```
