# IRD-004 — frontend-service

**Scope:** React SPA (web UI) — login, task list, create task, status update, add comment.  
**Linked DOP:** DOP-001 AC-08, AC-09, AC-10, AC-11, AC-12, AC-13  
**Depends on:** IRD-003 (api-gateway — all API calls go through the gateway)  
**Deployed as:** nginx Docker container serving a compiled React build on port 3000

---

## What this service does

`frontend-service` is a React single-page application compiled to static files and served by nginx. It is the only UI layer of the system. The browser loads the app from the nginx container (port 3000) and then makes all API calls directly to the api-gateway (port 8080). The container itself stores no state and runs no server-side logic.

## Pages and routes

| Route | Page | Auth required | Description |
|---|---|---|---|
| `/login` | `LoginPage` | No | Email + password form → `POST /auth/login` → stores JWT → redirects to `/` |
| `/` | `TaskListPage` | Yes | Lists tasks with status badges; role-based (lead sees all, member sees own) |
| `/tasks/new` | `CreateTaskPage` | Yes | Form to create a new task (`POST /tasks`) |
| `/tasks/:id` | `TaskDetailPage` | Yes | Task fields, status selector, comments list, add-comment form |

Unauthenticated access to any protected route redirects to `/login`.  
After a successful login, redirect to `/` (task list).

---

## Authentication flow

1. User submits the login form → `POST /auth/login` via api-gateway
2. On 200: store token in `localStorage` under key `auth_token`; store user object under `current_user`
3. All subsequent API requests include `Authorization: Bearer <token>` via Axios request interceptor
4. On any 401 response: clear `localStorage`, redirect to `/login`
5. On logout: clear `auth_token` and `current_user` from `localStorage`, redirect to `/login`

**Token storage:** `localStorage` — acceptable for this program scope. JWTs expire in 24h per IRD-001.

## API calls summary

| Component | Method | Gateway endpoint | Payload / query |
|---|---|---|---|
| `LoginForm` | POST | `/auth/login` | `{ email, password }` |
| `TaskListPage` | GET | `/tasks` | `?status=&assignee_id=` |
| `CreateTaskForm` | POST | `/tasks` | `{ title, description, assignee_id }` |
| `TaskDetailPage` | GET | `/tasks/:id` | — |
| `StatusSelector` | PATCH | `/tasks/:id/status` | `{ status }` |
| `CommentForm` | POST | `/tasks/:id/comments` | `{ body }` |

All requests include `Authorization: Bearer <token>`. The api-gateway validates the token and injects `X-User-Id` / `X-User-Role` before forwarding to downstream services.

## CORS requirement (gateway responsibility)

Because the browser sends requests from `http://localhost:3000` to `http://localhost:8080`, the api-gateway must enable CORS:

```
Access-Control-Allow-Origin: <CORS_ORIGIN>   (default: http://localhost:3000)
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

Add `CORS_ORIGIN` to `api-gateway/.env.example`. This is a **gateway responsibility** — the frontend does not set these headers. Task F-09 covers this change.

## Docker configuration

### Dockerfile

```dockerfile
# Stage 1 — build the React app
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ARG VITE_API_BASE_URL
ENV VITE_API_BASE_URL=$VITE_API_BASE_URL
RUN npm run build

# Stage 2 — serve with nginx
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

### nginx.conf

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;
  index index.html;

  # SPA fallback — all non-asset paths return index.html
  location / {
    try_files $uri $uri/ /index.html;
  }

  location /health {
    access_log off;
    return 200 '{"status":"ok","service":"frontend-service"}';
    add_header Content-Type application/json;
  }
}
```

### docker-compose.yml addition

```yaml
  frontend-service:
    build:
      context: ./frontend-service
      args:
        VITE_API_BASE_URL: http://localhost:8080
    ports:
      - "3000:80"
    depends_on:
      - api-gateway
    networks:
      - app-net
```

> `VITE_API_BASE_URL=http://localhost:8080` uses the **host** port because the browser (running on the host machine) calls through the exposed port, not through the Docker network.

## Non-functional requirements (frontend-specific)

These extend the project-wide NFRs in IRD-003.

| # | Requirement | Rule |
|---|---|---|
| NFR-F01 | SPA routing | nginx must serve `index.html` for all non-asset paths (`try_files $uri /index.html`) |
| NFR-F02 | Auth token | Stored in `localStorage` under key `auth_token`. Cleared on 401 or explicit logout. |
| NFR-F03 | No hardcoded API URL | API base URL comes from `VITE_API_BASE_URL` only — never hardcoded |
| NFR-F04 | Loading states | Every async operation shows a loading indicator; errors show a user-readable message |
| NFR-F05 | CORS | api-gateway enables CORS for `CORS_ORIGIN` env var (default `http://localhost:3000`) |
| NFR-F06 | Health endpoint | nginx serves `GET /health → 200 { "status": "ok", "service": "frontend-service" }` |
